AI 行业简报 Agent

用一句话要一份能被推翻的行业研判：每条判断都带证据、依赖假设，和"什么情况下你该改主意"。

Agent 骨架继承自课堂 demo5 业务层、检索、证据库、自检、档案系统为新增 全程 AI 驱动构建
1.1

设计理念

别人的简报告诉你发生了什么；
这一份告诉你凭什么这么判断、什么情况下该改主意。

面向愿意深究的读者。它不追"最新"，追的是"这条变化值不值得记、凭什么"。三处设计对应三件事：

主线 + 证据链

先给结论，再给支撑它的事实。把零散消息收成几条主线，降低理解行业动向的门槛。

依赖假设 + 推翻条件

明确写出这条判断依赖什么前提、哪个信号出现就该改主意。这是辅助判断，也是给自己一个持续关注前沿的抓手。

思考题

引导继续追问、指明往哪里深入，而不是停在"知道了"。

同一批事实，三种讲法

非专业 / 学习者 / 业内三个档位，差别不在字数，在术语密度与"要不要用行话省事"。档位在对话里自动推断，也可随时要求重跑。

来源

做简报的动机来自《人工智能导论》课程的实验；"辅助判断、引导思考"的导向来自我自己的阅读习惯——真正难的不是知道发生了什么，是知道自己为什么这么想。

1.2

演示 A1：看它长什么样

演示前先给一句预期："接下来你会看到它在搜什么、存了什么、判了什么。"

看三处

顶部徽章当前档案 · 档位 · 覆盖期 · 类型覆盖 · 一手率 · 入选/候选 · 模型
左对话 / 右轨迹回答只放正文；工具调用与返回字数在右栏，过程不污染结果
下面四页证据 / 账本 / 简报 / 设置，都是可查的数据，不是模型的复述

然后启动一次

缺省档：学习者 × 标准 × 7 天，约 5–13 分钟（取决于模型）。运行中会显示阶段条与已运行时长。

演示注意：运行期间切档案、换会话、删除都会被禁用——切档案会关掉 Agent 的事件循环，等于把这一期腰斩。这是刻意设计的锁，不是卡住了。

1.3

演示 A2：看它怎么做（时间不足可跳过）

如果时间允许，把右栏轨迹打开，讲三个时刻：

  • 检索时：中英双语各一轮，英文是常规动作，不是补救手段。
  • 入库时：候选被拒的理由会显示——窗口外、域名叫 arXiv、缺日期、跨站转载。
  • 交付时：先跑机械自检，不通过就不写文件；通过才落盘并记账本。
2.1

准备工作：先把 demo5 拆开

课堂 demo5 是一个课程助教 Agent。骨架能用，业务层全部替换。哪些留、哪些丢，是动手前必须定的事——不定就会一边改一边发现方向不对。

继承

  • 装配集中在一个函数
  • 流式事件归一化
  • 双层会话持久化（检查点 / 会话库）
  • 虚拟文件系统 + 权限表

改造

  • 工具层换成检索与抓取
  • 权限表按档案收窄
  • 工作流适配（skill 接进本应用）
  • 提示词：行为约束，不写人格

新增

  • 证据库（SQLite + MCP 工具）
  • 机械自检（11 条规则）
  • 运行生命周期与记录
  • 验收脚本

顺手处理的两件事

  • 历史提交里有误上传的环境变量文件，其中的 key 早已吊销；现在密钥只存在 .env，不进仓库，页面上也只显示前后各几位。
  • 提前备好两类 key：模型（阿里百炼、DeepSeek）与搜索（DeepSeek、博查、智谱、Tavily）。
2.2

消息来源：用四个可测的量选，而不是"看着更好"

检索源不是随便挑一个。技能要求"任意日期区间 + 每条带日期 + 能拿到一手载体"，这三条都能变成可测指标。

供应商条数延迟日期率窗口外一手结论

同一批查询（2 组 × 7 天窗口）实测。「一手」按官方域名 + 发布页路径判定，不看搜索引擎给的权威度。

双语检索不是补救，是常规

只搜中文时，一手率被锁在 5% 上下（博查为 0）：OpenAI、Anthropic、Meta、NVIDIA 的一手载体只有英文页，中文报道必然是二手编译。同一批查询加上英文检索与语言限定后，能到 15%（细分数见 3 的数据卡）。

探针顺带查出的三个事实（比选型更重要）

01
时间过滤是软的。给了窗口仍约有 5% 越界——入库时得自己再判一次日期，不能信检索参数。
02
重复率 10–15%，且是跨站转载。同一篇稿子会同时出现在网易、新浪、凤凰，只按 URL 去重拦不住。
03
"权威性"不等于一手。新浪财经能拿到最高档权威度，而它只是转载；BAAI 的原文反而更低。
2.3

骨架、工具、证据库、自检

这一节六个点，都挂在同一句话上——它决定了这个项目和"写一堆提示词"的区别。

记录外置：不靠模型记忆。交付可检出：不靠模型自觉。规则可执行：不靠模型自查。

① 工具返回什么，模型就怎么想

工具没有别的说明书，只有返回结构。三处实测后果：

没有 date 字段

模型会自己编一个日期补上。返回里加 date: null 明确表示"没有"，它才会丢弃这条。

带 authority 却不说清

新浪财经权威度 4、实为转载，会被判成一手。所以工具层只输出按域名与页面性质算出的「是否一手」。

降级不吭声

中文源失败切博查后，若不告诉模型"这是降级结果"，它会把中文转述当成英文维度的证据。

结论

工具层做的不是"取数"，是约束模型能得出什么结论。返回字段就是它的判断边界。

② 证据库：三条规则必须由代码执行

去重要两个键

url_norm + title_norm。前者拦同一页面的不同链接，后者拦同一篇稿子的跨站转载。

入库自己判窗口

检索参数是软的（2.2 实测约 5% 越界），所以窗口判定放在入库时做，不靠模型自觉。

一手要三条同时满足

官方域名 + 发布页路径（/blog/、/news/、/pricing）+ 真的抓过正文。

为什么要外置：技能里"同一信源只算一票、单信源最多供 2 个簇"是跨条目统计。让模型在几十条候选里数谁跟谁同源，必然出错，而且错了没人能发现。

③ 自检：把"不该做"变成"做不到"

技能里 24 条自检，18 条有客观答案，做成了 11 条机械规则：字数、条数、术语锚点、簇数与库一致、四要素齐全、事实段措辞、思考题结构、链接可溯源……

最硬的一条：正文里每个链接，必须能在证据库里查到。它把"禁止编造 URL"从道德要求，变成了一次必然失败的检查。

④ 验收脚本先打脸了写它的人

证据库探针第一轮 12/13 通过。错的那一条不是代码，是Agent自己写的断言——心算拒绝条数算错了。

这正好说明脚本的意义：它不替模型背书，它替你算一遍。如果只看 Agent 自述"我入库了 3 条"，这个错会一直留着。

⑤ 装配集中在一个函数

界面不含任何 Agent 知识，只调 build_agent() 与事件流。改能力只改一个文件，界面永远不用动。

权限表是顺序敏感的

1 先放行本档案的简报目录、账本目录
→
2 再挡密钥、虚拟环境、运行时数据、git
→
3 收口工作文档只读，其余一律拒绝写

第一条命中即生效。顺序写反会"静默失效"——看起来配了权限，实际一条都没生效。

⑥ 运行与记录

一次运行的生命周期曾经挂在页面上：流式循环写在页面函数里，切页面会让整个脚本中断、循环被丢弃；而"写会话记录"那句排在循环之后，于是永远不执行。结果很怪——运行照常完成、简报照常落盘，聊天记录却只剩提问。

改法：把"一次运行"做成独立对象，它自己跑到底、自己写记录；页面只负责看。配套加了运行中锁（切档案会关掉运行时，所以运行时禁用切换）与 25 分钟墙钟上限。

这条与 ⑤ 的权限表、② 的证据库是同一条原则：关键动作必须由代码持有，不能交给"页面还开着"，也不能交给"模型记得"。

2.4

界面与交互

先按计划做完，再按使用中暴露的问题改。下面每一项都对应一个真实的卡点，不是"顺手加的"。

与 demo5 相比改了什么

信息徽章 输入框固定在窗口底部 五页分离 + 顶部导航 页内配置环境变量 会话重命名 / 删除 档案系统（隔离历史） 模型可切换 运行时禁用会打断的操作

① 输入框钉不钉底，是容器问题不是样式问题

它原来写在左栏的 column 里，就是普通内联元素，跟着内容一起滚。框架只对主容器里的输入框做"固定到窗口底部"，移到页面根部就恢复了。看着像 CSS，实际是"元素挂在哪个容器"。

② 弹窗不能从弹出菜单里直接打开

在弹窗里点任何控件，整个脚本会重跑一次；此时"弹出菜单"已关闭，弹窗跟着消失。改法：把待办写进会话状态，在主流程里稳定渲染，直到确认或取消才清掉。

③ 档案系统：把路径从常量改成参数

原来证据库、会话、账本都是模块级常量。要支持多档案，只能改成"按档案算"的函数。那两个常量是故意删掉的——留着的话，漏改一处就会静默写回默认档案，界面上表现为"切了档案但内容没变"；删掉后，漏改的地方会直接报错。

写权限按档案收窄

A 档案读不到，也写不了 B 的目录。

记忆分两层

全局口径 + 档案偏好。每档案复制一份全局口径，改一条要改 N 份，必然漏。

删档案保留简报

简报是交付物，不是运行态。

④ 一处"静默失败"

删档案时，检查点库正被 Agent 打开，文件删不掉；而 ignore_errors=True 把失败吞了——界面显示删除成功，目录还在，重启后又冒出来。改法：先关运行时再删，删不掉就抛错。

它与上面"切页面丢记录"是同一个毛病：没有返回值、没有校验的动作，会安静地什么也没做。

⑤ 密钥与配置的三条

01
永不回显。输入框留空，只显示 sk-…a1b2，保存只提交改过的项。
02
改完必须让进程重新读。环境变量加载默认不覆盖已有值，不加 override 就是"界面保存成功、进程里还是旧值"。
03
只查"键在不在"不够。曾把百炼的 key 填成 DeepSeek 的（长度、前缀都像），只有真发一次请求才 401——所以设置页有「测试连通」。

deepseek-flash 是接口标识，服务端自动路由到当时最新的 flash 版本，本次全部验证跑在 v4.1-flash-1017 上。所以这份成果也可以当作对 1017 的一次测试：同一套工具、同一句提问、五十多次工具调用，它能一次跑完并自己交付。

对照不是为了评"谁更聪明"，而是看交付纪律与上下文控制。max 档判完 52 条证据、标了 32 条入选（配额 6–8），采集过猛把上下文撑大，随后卡在一次模型调用上——判据是"无新事件"，不是"感觉慢"。

3

Skill 的边界条件与判断标准

每条规则背后，都得有一次具体的错误。

这一节不讲怎么写技能文档，讲那些数字和条件是怎么定下来的：定大了会怎样、定小了会怎样、错一次之后改成了什么。

01

配额是算出来的

1–3 天窗、深度档：簇数 6–8，主线却仍是 3 条 —— 平均每条主线 2.3 簇，而主线的准入门槛就是 2 簇，等于零冗余。

配额表里篇幅管主线数、窗口管簇数，两个维度各自独立。窗口一缩，簇数降下来、主线数没动，每条判断就都贴着淘汰线。把 1–3 天档的主线数改为 2 条后，比值回到 3.0–4.0，与 7 天窗持平。

代价：定 3 条，第三条必然靠单簇硬撑；定 1 条，一周里真正有位移的线常有两条，第二条被浪费掉。

02

短窗要横向并发

10-20 那期，治理类在三天内有三个主体各自动作（一家公布内部编制数据、一家累计披露 19 起失控、一家出席市议会听证）。旧规则把它们拆进两条不同主线，新规则识别为同一条线的并发信号。

长窗靠"一件事变了几次"补深度；短窗没有纵深，唯一不可替代的是"同一维度多主体在同几天出牌"。这个密度信号必须显式检测（同一事件线独立主体 ≥3 才算），不能指望写的时候自然浮现——不检测就一定漏。

代价：不检测，三条各自独立的事件被平摊进不同判断，密度信号消失；检测过头，把"同趋势不同主体"并成一个簇，违反合并判据。

03

什么算值得记

拿 10-13 那期的 12 条新闻回测，3 条判为无位移（一块 192GB 统一内存、一颗 LPDDR6、一个多模态模型），理由都是"同维度再出牌、分数比平"。

判据从"影响多大"换成"有没有发生不可逆的位移"。开源权重收不回来、监管生效改变合法性边界——算；融资能再融、发布会能跳票、榜单下次就被破——不算。用热度和讨论量判断，会被营销词牵着走。

代价：收紧判据会漏掉当时热闹的事——回测的直接结果是条数从 12 降到 7。这是密度的代价，不是失误。

04

够格看证据

一手率只搜中文 5%，加语言限定能到 15%——但真正的区别是它变成了一条规则：一手率低于三分之一时，必须在方法论备注里写明缺口方向。

主体清单里国外公司的一手载体只有英文页，中文报道必然是二次编译。不把双语做成常规动作，一手率的天花板就锁死在 5%，而规则又要求写明缺口——一期一期写"本期无一手"，等于把缺陷常态化。

代价：不做，报告永远靠转述；做了但允许"英文失败用中文顶替"，英文维度就是假的，而报告照常写"已做双语检索"。

05

承认没拿到

类型覆盖不足时，头部照实写「类型覆盖 5/6」；窗外事件每期最多 2 条可作边界条目，且不占 48 小时新近配额。

静默补齐比缺一维更贵。读者看到六条齐整的简报，会以为各类都在动；看到 5/6，一眼知道缺的是哪一维。边界条目限 2 条，是因为 10-23 那期窗内 7 簇、窗外另有 5–6 条有位移的事件——全放进来就是偷偷扩窗。

代价：不限 2 条，三天简报写成一周边；不写 N/6，读者无从判断这期是否偏科。

06

能被下一期打死

短窗主线的推翻条件，观察窗口必须 ≤ 下一期。写"观察六个月内是否出现 X"的判断，在这套流程里永远无法回检。

账本每期回检上期的推翻条件，判成立／已被推翻／仍待验证；另有四条时效规则管"未尘埃落定的事"——7 天内保留、7 天无进展丢弃、7 天有进展重写续期、14 天不再专门搜索。没有时效，账本会积一堆永远待确认的条目，回检成本逐期上升，最后没人读。

代价：不设观察窗口，判断永远"待验证"；不设过期，账本从校准工具退化成备忘录。

07

应用打回三条

装进 Agent 跑五期后，主版本被打回三条：双语是常规动作不是补救、自检要工具化、账本不能跨档案回检。

三条都是"用起来才发现"的。最典型的是模型跳步——报告写出来了，没落盘、没跑自检，仍声称已完成；改成一次调用、返回成功标志才有约束力（2.4 的自动补救就是它逼出来的）。另一条是：一手率从 5% 到 15%，只差一个语言维度。

代价：不合并，每个接入方都要重新踩一遍；合并过头，把应用专属的路径与工具名写进主版本，主版本根本执行不了。
