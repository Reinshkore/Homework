# 报告骨架与账本格式

骨架只固定**顺序与字段**，不固定措辞。单条结构的内部写法查 `audience.md`。

## 一、通用头部

```markdown
# AI 行业动向研判 · <YYYY-MM-DD>

档位：<受众> × <篇幅>（<缺省则注「未指定」>）　覆盖期：<起> — <止>　事件簇：<N> 个　位移事件：<M> 个　类型覆盖：<K>/6
```

档位行必须有。读者看到档位不对可以直接要求重跑，这是省掉一轮追问的代价补偿。

覆盖期与簇数照实写。「位移事件数」与「簇数」分开写：簇里可能含无位移的观察项，混在一起会虚增份量。「类型覆盖 K/6」按 T1–T6 实到几类计，不足 5 类时按 `pipeline.md` 六之三处置后照实写，不补齐、不四舍五入。

**K 与 M 都从 `evidence_query(view="stats")` 取**：`coverage` 就是 K，已判定（`judged`）与 `in_report` 给出 M 与簇数。不要手数——手数是必然出错的一步，而且错了没人能发现。

若发生扩窗或降档，另起一行注明：`注：本期扩窗至 X 天／已降为 N 簇，未达深度档基线`。用户显式指定窗口时不扩窗，只写 `注：指定窗口内合格事件 N 个，低于本档基线 M`。

## 二、上期回检（有账本才出现）

```markdown
## 上期回检

- 上期判断：<一句话>
  - 推翻条件：<一句话>
  - 本期状态：成立 / 已被推翻 / 仍待验证（附一句依据）
```

无账本则整节删除，不留标题。

## 三、主线块

### 精简档（1 条）

```markdown
## 本期主线

**<可证伪的判断句>**

依据：<事件 A>（<日期>）、<事件 B>（<日期>）。<一句串起因果>。

我可能错在：<一句话，即推翻条件的简写>。
```

### 标准档（2 条）

```markdown
### 主线 N — <可证伪的判断句>

- **证据**：<簇 A>（<信源>，<日期>）；<簇 B>（<信源>，<日期>）
- **依赖假设**：<这条判断隐含的前提>
- **推翻条件**：<什么证据出现就该放弃>
```

### 深度档（3 条）

```markdown
### 主线 N — <可证伪的判断句>

- **置信度**：高／中／低　|　为何不更高：<一句话>
- **证据**：<簇 A>（<信源>，<日期>，<A/B/C>）；<簇 B>（<信源>，<日期>，<A/B/C>）；<簇 C>…
- **依赖假设**：<前提，逐条列>
- **推翻条件**：<可观测证据 + 观察窗口>
- **相邻判断**：<这条与另两条主线的交叉或张力>
```

深度档的三条主线必须写出彼此关系。三条互不相干的判断凑在一起，说明它们本来不该同时存在。

### 三之一、短窗追加：事件线

窗口 ≤3 天时，每条主线在「置信度」之前加一行（没有置信度项的档位，加在标题下第一行）：

```markdown
- **事件线**：<窗外锚点（日期）> → <窗内事件（日期）> → <窗内事件（日期）>
```

一句话，不展开，不占单条字数配额。窗外事件只出现在这一行与依赖假设里，不进事件明细与证据表（`short-window.md` 一节）。

## 四、事件明细

### 非专业 · 三跳

```markdown
### N. <标题，不用术语>

<YYYY-MM-DD>｜<信源名>｜[原文](<深链>)

**发生了什么**：<一句，无缩写、无参数、无评测集名>

**凭什么说它重要**：<以前的对照 vs 现在的对照，须能用常识判断>

**会先影响到谁**：<具体场景或职业>
```

### 学习者 · 五段

```markdown
### N. <事件标题>　[L2 模型与训练]

<YYYY-MM-DD>｜<信源名>｜[原文](<深链>)

**发生了什么**：<1–2 句，纯事实>

**改动在哪一层**：<层，以及是否波及相邻层>

**为什么能做到**：<1–2 句，带前置条件>

**还差什么**：<1 句，失效条件>

`<术语>`：<≤20 字定义>
```

### 业内 · 四段

```markdown
### N. <事件标题>　[L3]

<YYYY-MM-DD>｜<信源名>（<A/B/C>）｜[原文](<深链>)

**增量**：<省掉已知前提，只写这次变了什么>

**机制**：<关键取舍，收益与代价同时写，数字标口径>

**与我相关**：<架构选择／成本模型／评估口径，落到具体动作>

**不确定处**：<哪个数字是厂商口径、缺什么数据、什么条件下改判>
```

## 五、证据表（仅深度档）

放在事件明细之后、思考之前。

```markdown
## 证据表

| # | 事件 | 日期 | 类型 | 影响半径 | 确定性 | 信源 | 一手 |
|---|---|---|---|---|---|---|---|
| 1 | <事件> | MM-DD | T3 | 4 | A | <信源> | 是 |
```

「一手」列写是／否。全表一手率为 0 时，必须在表下注明「本期无一手信源，全部结论依赖二手转述」。

## 六、提请注意与未入选观察（按需）

两栏并列，**顺序固定：先提请注意，后未入选观察**。前者对读者有行动价值，后者只是交代。

### 6.1 提请注意（仅窗口 ≤3 天）

给「刚发生、影响半径自评 ≥4、但未达准入」的事件。写法固定两句，只指路，不作判断：

```markdown
## 提请注意

- <事件>（<日期>）：未入选因为 <一句话>。要看进展，盯 <具体源> 的 <具体指标>。
```

上限：非专业 1、学习者 1；业内 精简 1、标准 2、深度 3。**默认只写 1 条**，只有多条关注价值都很高时才并列。细则见 `short-window.md` 第三节。

### 6.2 未入选观察

位移判定为「无」或「存疑」的事件不进正文，但可以放这里，一行一条。作用是让读者知道「热闹但不重要」的那些事我看到了，而不是漏了。

```markdown
## 未入选观察

- <事件>（<日期>）：<一句话说明为何无位移——同维度再出牌／分数比平／纯集成>
```

条数不设限，但不写解读、不写影响。这一节只做交代，不做分析。

## 七、思考

```markdown
## 本期思考

1. **校验型**　<问题>
2. **外推型**　<问题>
3. **反证型**　<问题>

> 若以上答不上来，按卡住的原因选退路：不知道数算大算小 → 见下第 4 条；不知道跟自己有什么关系 → 见下第 5 条；拿不到行业内部数据 → 本期不要求作答。

4. **学习者档**　<换落点的同一件事>
5. **非专业档**　<换落点的同一件事>
```

条数：精简 2 条（校验 + 反证），标准 2–3 条，深度 3 条；降档入口另计（学习者 +1、业内 +2，合计上限 5）。

降档题只挂在主档用过的那条主线上，选读者最可能卡住的那条（依赖厂商口径最多或置信度最低）。「本期不要求作答」这一行不是客套，缺了它读者会因为一道题否掉整份报告。

## 八、方法论备注（≤3 行）

写明检索方向、信源缺口、组合档位、是否含回声簇与无位移观察项。不含投资建议。

## 九、账本格式

文件：`/docs/ledger/<档案>/.ai-brief-ledger.md`（`<档案>` 见系统提示词；同一档案内固定）。追加写，不覆盖，每期一段。

该文件名以点开头，列目录时须带 `-a` 才能看到。判断「账本是否存在」之前，先确认自己看的是不是隐藏文件列表——2026-10-23 曾因这一点误判账本丢失，另建了一份。

```markdown
## <YYYY-MM-DD>｜<受众> × <篇幅>｜窗口 <N> 天｜覆盖期 <起>–<止>

### 主线 N

- 判断：<一句话>
- 位移类型：能力／成本／可及性／供应链／约束
- 依赖假设：<一句话>
- 推翻条件：<一句话>
- 置信度：高／中／低（精简档可省）
- 状态：待验证

### 悬置事项

| 事件 | 状态 | 下期该看什么 | 关联主线 | 起始 | 截止 |
|---|---|---|---|---|---|
| <事件（日期）> | 待确认／待推翻 | <具体指标> | 主线 N／— | MM-DD | MM-DD |

### 本期检索缺口

- <方向>：<原因或空结果>
```

### 9.1 悬置事项是什么

记录「还没尘埃落定的事实」，与「推翻条件」分工不同：

- **推翻条件针对判断**——若 X 出现，这条判断作废（逻辑反证）
- **悬置事项针对事实**——这件事还没落地，下期看它落到哪（经验未决）

每条自带一句话说明，禁止写「见上期正文第二节」——读者可能没保留往期简报，账本要能脱离正文独立读懂。

### 9.2 过期与续期

三档处理，按天数控，不靠判断：

| 条件 | 处理 |
|---|---|
| 距起始 <7 天 | 正常保留，下期继续看 |
| ≥7 天，且本期检索无进展 | **丢弃**，不再列入 |
| ≥7 天，有最新进展但仍无定论 | **重写该条**（更新状态与观察指标），起始日改为本期，等效续期 |
| >14 天 | 视为过期，**不再专门搜索**；若检索中偶然获得定论，补写一句结论后移入归档 |

理由：不设过期，账本会积一堆永远「待确认」的条目，回检成本逐期上升，最后没人读。悬置的价值在于被消化，不在于被保存。

### 9.3 改口必须显式

若本期结论与上期某条已标「推翻」的判断方向相反，必须写一句「上期判为推翻，本期证据转向，原因是……」。禁止静默改口——账本的全部价值在于校准，静默改口等于擦掉校准数据。

下期执行 Step 0 时只读最后一节，逐条对照新结果改写状态、按 9.2 处理过期。历史条目一律不动——账本的价值在于保留当时的判断，事后修改等于自欺。

## 十、落盘规则

| 场景 | 行为 |
|---|---|
| 每期（默认） | 正文由 `publish_brief` 写入 `/outputs/briefs/<档案>/ai-brief-<受众>-<篇幅>-<YYYY-MM-DD>.md`，以返回的 `path` 为准 |
| 用户说「只在对话里给我看」 | 不落盘正文，但账本照记 |
| 每期执行完 | 追加账本到 `/docs/ledger/<档案>/.ai-brief-ledger.md` |
