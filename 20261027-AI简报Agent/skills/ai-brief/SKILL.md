# Industry Brief

## Overview

把一段时间窗内的行业事件，压缩成少量可被证据检验的主线判断，摊开其依据与不确定性，最后把判断权交回读者。

产出的不是新闻列表，是研判简报：读者读完应当知道「发生了什么结构性变化」「这个变化卡在技术栈的哪一层」「该用什么问题继续往下想」。

## When To Use

- 要求汇总某段时间的行业动向、变化、重要事件
- 要求做行业简报、月度观察、赛道梳理
- 触发短语：「最近 AI 有什么动向」「做一份 AI 行业简报」「这个月 AI 领域有什么变化」「industry brief」

不适用：

- 单条新闻的解读或追问 → 直接回答，不启动流程
- 公司尽调、个股分析、投资建议 → 需要财务与估值能力，本技能不覆盖
- 要求预测具体时间点的趋势 → 本技能只给可证伪的判断与推翻条件，不给预测

## 当前版本边界（v0.7.1-app）

| 参数 | 可选值 | 缺省 | 状态 |
|---|---|---|---|
| 行业 | AI（不再扩展其他行业，转而加深本行业的判定精度） | AI | 锁定 |
| 受众 | 非专业 / 学习者 / 业内 | 学习者 | 已开放 |
| 篇幅 | 精简 / 标准 / 深度 | 标准 | 已开放 |
| 时间窗 | 1–3 天 / 4–10 天 / 11–45 天 / >45 天 | 7 天 | 已开放，受篇幅配额与边界条款约束（`pipeline.md` 六之二） |

不主动询问参数。定档规则见 `references/triage.md`：信号分五层，用途比身份可靠，判断不问身份。缺省取「学习者 × 标准 × 7 天」——理由是它是信息不丢失的下界，不是因为它居中。

报告开头用一行注明采用的档位；若是缺省值，一并注明「未指定」。读者看到不对可直接要求重跑，比追问一轮省时间。

## 运行时工具

宿主提供 10 个工具。流程里凡写「检索」「入库」「查库」，指的就是下面这些，不要用别的方式代替。

| 工具 | 用途 | 关键约束 |
|---|---|---|
| `web_search` | 按事件类型检索 | `lang`（zh/en）、`start`/`end`、`count`（≤10）、`site` |
| `fetch_page` | 抓单个网页正文 | 只在认定一手或核对细节时用 |
| `evidence_add` | 候选事件入库 | 采集后**立即**入库，不要把候选留在对话里 |
| `evidence_query` | 读库 | `view`：rows / stats / clusters / sites |
| `evidence_update` | 写回判定 | 位移、半径、确定性、簇号、是否入选 |
| `brief_lint` | 格式自检（8 条机械规则） | 一般不用直接调：`publish_brief` 内部会跑；单独调用于交付前预检 |
| `publish_brief` | **交付**：自检 + 落盘 + 记账 | 返回 `published=true` 才算交付；不要用 `write_file` 代替 |
| `resolve_window` | 算时间窗 | 报告头与账本的时间一律取自它，不要自己算 |
| `get_current_time` | 当前时间 | — |
| `calculator` | 算术 | 数字换算不要心算 |

**顺序是硬的：检索 → 入库 → 判定 → 写回。** 跳过入库直接判定，后面的去重、类型覆盖、一手率全部失去依据。

三条实测口径，与本技能原有判据配合使用：

1. **补一手用 `site:`，但 `/docs/` 页不算发布载体。** 实测 `site:minimax.io` 返回的全是 `platform.minimax.io/docs/*` 的 API 文档页；`site:github.com` 返回的是第三方仓库的接入 PR。判断一手看页面是不是发布页（`/blog/`、`/news/`、`/releases/`、`/pricing`、`/models/`），不能只看域名。
2. **`authority` 是站点权威度，不是一手。** 新浪财经能拿到最高档（4），BAAI 智源只有 3。禁止用 authority 填证据表的「一手」列。
3. **英文维度检索失败时不得用中文结果顶替。** 按该类型空白处理并写进「检索缺口」。否则「已做双语检索」是假的。

检索配额：每期 24 次（含降级重试）。`evidence_query(view="stats")` 只需调一次，不要反复换视图确认同一件事。

## Workflow

### Step 0 — 定档与回检

**先定档**（成本极低，且决定后面所有环节）。按 `references/triage.md` 定三个参数：受众、篇幅、时间窗。信号按 L1 显式 → L2 用途 → L3 词汇 → L4 窗口 → L5 缺省 的顺序取，前一层覆盖后一层。判不出就取缺省，不追问。

工作区若存在 `/docs/ledger/<档案>/.ai-brief-profile.md`，先读它——上一次被纠正过的档位优先于缺省值。**`<档案>` 是系统提示词给出的当前档案目录**，不要用别的档案的。

**再回检**。工作区若存在本档案的 `/docs/ledger/<档案>/.ai-brief-ledger.md`，读最后一条记录，把上期的每条「推翻条件」对照本期检索结果，判定为成立／已被推翻／仍待验证，写进「上期回检」小节；同时处理上期的「悬置事项」——按 `report-skeleton.md` 9.2 判保留、丢弃、续期或过期，过期的不再专门搜索。无账本则跳过，报告中不出现该小节。**不要回检别的档案的账本**：档案之间互相隔离，混读会把不同读者的判断口径混在一起。

**窗口 ≤3 天时载入 `references/short-window.md`**，它会改变后面所有环节（事件线、上下文窗分级、并发检测、主线数下调、提请注意栏、检索配额）。长窗不载入。

### Step 1 — 载入行业标尺与位移判据

读 `references/industries/ai.md`，取六样东西：主标尺、五类位移、不重要清单、事件类型、信源白名单与排除项、关键主体。

其中**五类位移是判定「什么重要」的核心**。没有它，检索只能得到热度排序；有它，才能在采集阶段就筛掉「同维度再出牌」的事件。

### Step 2 — 采集

按**事件类型**并行检索，不按关键词。事件类型见 `industries/ai.md` 第五节。

**双语是常规动作，不是补救手段。** T1／T3／T5／T6 四类除中文检索外，各加一轮英文检索（同一语义的英文表述，`lang="en"`）——国外主体的一手载体只有英文页，中文报道必然是二手编译。T2／T4 可只做中文，这两类的中文生态（阿里、字节、华为、商汤）比英文源密。英文检索失败时按该类型空白处理，**不得用中文结果顶替**。

每个候选项记录五个字段：`日期 / 主体 / 事件类型 / 信源（媒体名 + 原文深链）/ 是否一手`，并在本轮检索结束前全部交给 `evidence_add`。

一手 = 官方公告、产品页、定价页、监管文件、公司技术博客、代码仓库 release。二手 = 媒体转述。**若用 `fetch_page` 抓过正文，把返回的字符数填进 `fetched_chars`；没抓过就不要填——一手只认真的读到过原始载体。**

覆盖的事件类型数：精简 ≥3 类，标准 ≥5 类，深度 ≥5 类（窗口 ≤3 天时按 `short-window.md` 第五节下调为 3／4／5）。日期不确定的直接丢弃。**覆盖不足时不得静默凑数，按 `pipeline.md` 六之三处理：先补定向检索（每类 ≤2 次查询），仍不足则按实际覆盖输出并在头部写明「类型覆盖 N/6」，不得用同一类型的第 4 个簇去伪装多样性。**

### Step 2.5 — 证据入库

本轮检索结束，**立即**调用 `evidence_add(items, window_start, window_end, audience, length)`。

- 检索结果里的每一条都要进 `items`，不要挑「看起来重要」的先进——挑拣是 Step 3 的事，入库只负责把候选固定下来。
- 工具会替你拒绝：窗口外日期、技能排除的域名、缺日期、重复的 URL 与跨站转载。被拒的条目**不要改个字段重试**，那是绕过规则。
- 返回里 `rejected` 与 `skipped_duplicate` 各有多少、为什么，记下来，最后写进「检索缺口」。
- **本期若此前已跑过**（同一窗口同一档位），第一次调用传 `reset=true` 先清掉旧证据。不清的话，上一轮的入选标记与簇号会混进这一轮，簇数、一手率全部失真。增量采集（边搜边入库）必须留 `false`。

入库之后，判定阶段的依据是库，不是对话里的检索结果。**不允许「我记得刚才搜到过」这种说法。**

### Step 3 — 判定与压缩

1. **取表 + 位移判定**（先做这一步，早于打分）：先 `evidence_query(view="rows")` 取候选表，再逐条比对五类位移与不可逆性检验，结果用 `evidence_update(ids, {...})` 写回。无位移的标 `displacement="none"`，降入「未入选观察」，不进簇、不进主线，哪怕半径很大。
2. 同一事件的多源报道合并为一个**簇**：给这批 id 写同一个 `cluster_id`（正整数），并把 `form` 填成 `fermenting` 或 `echo`。合并判据见 `pipeline.md` 第五节，注意「同趋势不同主体各自成簇」。
   **合并完必须调 `evidence_query(view="clusters")` 核对**：若每个簇的 `source_count` 都是 1，说明一条都没合上，回到本步重做。报告头的「事件簇」数取自这个视图的簇个数，**不取入选条数**。
3. 簇形态的判据是信息增量而非报道次数，见 `pipeline.md` 四之一 B。写完用 `evidence_query(view="clusters")` 核对每个簇的信源数，别靠回忆。
4. **短窗追加：并发检测**。统计同一事件线在窗口内的独立主体数，≥3 个主体各自动作即标「并发信号」，优先占用主线名额。只加权、不合并簇（`short-window.md` 2.4）。
5. 排序（定义见 `pipeline.md`，必须按定义走）：
   - 影响半径 1–5
   - 确定性 A/B/C
   - 过时间闸门：新近配额、陈旧衰减、发布不足 12 小时的确定性上限
6. 取够配额的事件簇。配额受**篇幅与窗口双重约束**，见 `output-spec.md` 第一节与第一节之一——窗口越长，簇数越少。选中的条目用 `evidence_update(ids, {"in_report": 1})` 标记，没选中的保持 0——证据表的「未入选观察」直接由它筛出来。

### Step 4 — 主线成型

写 N 条主线判断，N 由篇幅与窗口共同决定：常规 精简 1 条、标准 2 条、深度 3 条；**窗口 ≤3 天时下调为 1／1／2**（`short-window.md` 2.1）。每条必须包含四件东西，缺一件就不算主线：

1. **判断** — 可被证伪的陈述句，不是话题概括
2. **证据链** — 挂 ≥2 个**事件**簇，标明各自信源。横截面证据（定价表、榜单、规格表）不计入，只能作背景
3. **依赖假设** — 这条判断隐含了什么前提
4. **推翻条件** — 出现什么可观测证据，这条判断就该被放弃

「AI 行业持续快速发展」不是判断，它无法被证伪。凡不能设想出推翻条件的主线，直接重写。

深度档额外要求：每条主线给置信度（高／中／低），并写明为什么不给更高一档。

### Step 5 — 按档位写

先查 `references/output-spec.md` 第一节取篇幅配额，再查 `references/audience.md` 取该受众的单条结构：

| 受众 | 单条结构 |
|---|---|
| 非专业 | 三跳：发生了什么 → 凭什么重要 → 先影响谁 |
| 学习者 | 五段：发生了什么 → 改动在哪一层 → 为什么能做到 → 还差什么 → 术语锚点 |
| 业内 | 四段：增量 → 机制 → 与我相关 → 不确定处 |

篇幅只决定条数、字数与附加项（深度档加同类对照、机制细节、证据表），不改变结构。

### Step 6 — 思考引导

按 `references/inquiry.md` 生成 2–3 个主档问题。铁律：不给答案、不暗示答案、不用「你怎么看」。

思考题的深度跟着受众走：非专业档问「这跟你的判断是否一致」，业内档问「你会改哪一步」。

**向下兼容**：业内档另附学习者档 1 条、非专业档 1 条；学习者档另附非专业档 1 条；非专业档不附加。降档题必须挂在同一批证据上，选读者最可能卡住的那条主线，换落点不换话题。同时给出一条退回判据，让读者知道「答不上」是该降档、还是本期不要求作答（`inquiry.md` 第六节）。

退回判据**用标签引用，不用序号**（「见下方非专业档那条」）：条目数随档位变，写成「见第 5 条」在学习者档就指向空气。学习者档的「数算大算小」这条退路没有对应题，写「本期不要求作答」。

### Step 7 — 交付：自检、落盘、记账（一次调用）

**一次调用完成，不要拆成三步文件操作。**

1. 按 `assets/report-skeleton.md` 写好正文（含头部档位行）。
2. 按同一文件第九节写好账本片段。
3. 调 `publish_brief(markdown, ledger_entry, audience, length, window_days, period_id)`。
4. 返回 `published=false` → 按 `violations` 逐条改正文，再次调用。**最多两轮**；两轮后仍有 error，在正文尾部加一行「本期未通过自检：N 条」再提交。
5. 返回 `published=true` → 用返回的 `path` 告诉用户。**只有拿到 true，本期才算交付。**

两条硬规则：

- **不要用 `write_file` 写简报或账本。** 那条路绕过自检，跳步时没人会发现。实测过一次：模型写完分析直接在对话里出报告，既没落盘也没自检，结尾还声称「文件路径：/outputs/briefs/...」。
- 最后回复给「一句话摘要 + 档位 + 文件路径」，**不要把全文再贴一遍**——正文已经在文件里，贴一遍等于交付了两份不同的东西。文件路径用 `publish_brief` 返回的 `path`，它已带档案子目录。

用户纠正过档位时，把纠正记进 `/docs/ledger/<档案>/.ai-brief-profile.md`（格式见 `triage.md` 第六节，`<档案>` 取系统提示词给出的当前档案目录）。

## 硬性规则

- **位移优先于半径**：没有位移的事件，半径再大也不进主线。半径只决定排位，不决定入选。
- **结构即标记**：事实只写在「发生了什么」段，推断只写在「为什么能做到」「还差什么」段，观点只出现在「判断」块。禁止在事实段使用「将」「即将」「意味着」。
- **证据只看事件**：定价表、榜单、规格表是横截面，不能计入主线的证据簇。
- **同源只算一票**：同一 URL、同一篇聚合文的条目，对一条主线只提供一次证据；共用信源的簇确定性降一级。
- **回声不计分量**：只增加评论与转载的后续报道不算新信源；70% 以上为回声的簇，排序降一档且不得进证据链。
- **新近必有**：每期至少 1 条（深度档 2 条）发布在最近 48 小时内，即使半径低于更早的事件。
- **未满 12 小时的事件确定性封顶 B**：只判断影响路径是否明确，不判断影响大小。
- **信源冲突**：两个都写，标明分歧点，不选边。
- **不编造 URL**：搜不到原文深链就退到权威转述，注明「据 X 报道」。
- **区分已发生与已宣布**：发布会宣布的路线图属于已宣布，正文必须写明。
- **数字标口径**：业内档每个数字后标（厂商宣称）／（第三方实测）／（估算）。
- **不凑数**：为凑够簇数而纳入不满足准入的事件，比少写几条更糟。
- **不跳步**：检索 → 入库 → 判定 → 写回，四步顺序不可换。跳过入库直接判定，等于放弃了去重与统计。
- **一手只看载体**：官方域名 + 发布页 + 真的抓过正文，三条同时满足。`authority` 高不代表一手。
- **英文失败不顶替**：英文检索拿不到结果就按空白处理，不得用中文结果冒充英文维度。
- **stats 只查一次**：`evidence_query(view="stats")` 调一次就够，反复换视图确认同一件事是浪费。
- 政治与监管内容只做事实转述，不做立场评论。涉及地区与公司按官方表述。

## Changelog

- **v0.7.1-app** — 修「思考题退路引用越界」（2026-10-27）。现象：学习者档只有 4 条思考题，却写「见第 5 条」。根因两处：① `assets/report-skeleton.md` 第七节把**业内档**的条目序号（1–3 主档 + 4 学习者 + 5 非专业）当通用模板写死，学习者档照抄即越界；② `inquiry.md` 6.3 的退路表默认「主档位高于退路」，没写主档位就是学习者档时怎么办。改法：模板按档位分开给；退路**一律用标签引用**；学习者档的「数算大算小」退路改为「本期不要求作答」。配套新增 lint 规则 L12（退路引用的条目必须存在），`quality.md` 第 15 条同步。**这条属 B 类，应回合主版本**——上游 v0.6.1 同样有。

- **v0.7.0-app** — 应用适配版（2026-10-24，AI 行业简报 Agent）。改动只涉及「工具接入与落盘协议」，**判定规则一条未动**。① 新增「运行时工具」节，声明 8 个工具与硬顺序（检索 → 入库 → 判定 → 写回），并写死三条实测口径：`site:` 只到官方域、不到发布页；`authority` 不等于一手；英文失败不得用中文顶替。② 新增 Step 2.5 证据入库，采集后立即 `evidence_add`，被拒条目不得改字段重试。③ Step 2 把双语从"补检手段"升为常规动作：T1／T3／T5／T6 各加一轮 `lang="en"`，T2／T4 只做中文。④ Step 3 改为基于 `evidence_query(view="rows")` 的候选表判定，结果用 `evidence_update` 写回。⑤ 新增 Step 7 交付动作：`publish_brief` 一次完成自检、落盘与记账，返回 `published=true` 才算交付；禁止用 `write_file` 绕过自检（实测过一次模型直接出报告、没落盘也没自检还声称文件路径）。⑥ 产出默认落盘到 `/outputs/briefs/`，账本与档位偏好迁到 `/docs/ledger/`。⑦ 头部「类型覆盖 K/6」改从 `stats.coverage` 取，不再手数。⑧ 硬性规则补四条。改动清单与回合主版本的分类见应用仓库 `docs/ai-brief改动记录.md`。

- **v0.6.1** — 账本位置固定为 `docs/.ai-brief-ledger.md`（原为工作区根目录，用户要求迁入 `docs/`）。`SKILL.md` Step 0 与 Step 7、`report-skeleton.md` 第九节同步改，并补一句「文件名以点开头，`ls` 需带 `-a`」——2026-10-23 曾因未读到隐藏文件而误判账本丢失、另建一份，两份已合并。
- **v0.6** — 短窗（1–3 天）独立成章，保留判断导向。新增 `references/short-window.md`（八节）：① 事件线——窗外锚点只作序列定位，不得进事件明细与证据表，且须仍在发酵，窗内簇占证据链 ≥2/3；② 上下文窗按事件线类型分级（T1 7 / T2·T5 14 / T3·T4 30 / T6 45 天），不再统一 7 天；③ 并发检测——同一事件线窗内独立主体 ≥3 即标并发信号、优先占主线名额，只加权不合并簇；④ 主线数随窗口下调为 1/1/2（原为 1/2/3，导致短窗深度档簇/主线比仅 2.0–2.7）；⑤ 判断须短周期可证伪，推翻条件的观察窗口 ≤ 下期；⑥ 主线句须含窗内主体或数字；⑦ 提请注意栏与未入选观察分立，上限随档位（非专业/学习者 1；业内 精简 1、标准 2、深度 3，默认 1）；⑧ 检索配额与类型覆盖下调（≤3 天为 3/4/5）。账本新增「悬置事项」节与过期续期规则（<7 天保留；≥7 天无进展丢弃；≥7 天有进展重写续期；>14 天不再专门搜索）。`output-spec.md`、`pipeline.md`（六之四路由）、`quality.md`（自检 21–24）、`report-skeleton.md`（三之一、六、九）同步改。
- **v0.5** — 思考题向下兼容。`inquiry.md` 新增第六节：业内档另附学习者、非专业各 1 条，学习者档另附非专业 1 条，非专业不附加；降档题必须挂在同一批证据上、选读者最可能卡住的主线、换落点不换话题；给出三分退回判据（不知道数算大算小 → 学习者；不知道跟自己有什么关系 → 非专业；拿不到内部数据 → 本期不要求作答）。条数上限：非专业 3、学习者 4、业内 5，降档题不计入 `output-spec.md` 的「思考题（主档）」行。`SKILL.md` Step 6、`report-skeleton.md` 第七节、`quality.md` 自检第 15 条同步改。
- **v0.4** — 短窗实测暴露的三个规则缺口补成判据，不引入新档位。① `pipeline.md` 六之二：把「事件发生日」与「首次可公开查证日」分离，1–3 天档允许「发生日落在窗口前 48 小时内、查证日落在窗内」的条目入选，标记为边界条目，每期限 2 条且不占新近配额；4 天以上档不适用。② `pipeline.md` 六之三：事件类型覆盖不足的处置顺序（补检索 → 按实际覆盖输出 → 头部标 N/6），禁止用同类簇充多样性。③ `quality.md` 降级链新增「一手认定」：一手只按是否读到原始载体判，未见官方页即降 B、证据表「一手」列记否；官方页检索不到时补搜 ≤2 次，仍无则引权威转述并注明「据 X 报道」。④ `pipeline.md` 三之二补操作化：同一聚合源的第 3 条候选必须另找独立源才能成簇，采集阶段即执行，不留到判定阶段返工。⑤ 报告头部与骨架新增「类型覆盖 N/6」，与簇数、位移数并列。
